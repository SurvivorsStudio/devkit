# 세션 기록 남기기

이번 세션의 **결정과 그 이유**를 레포 루트의 `.done/` 에 파일로 남깁니다.

> `.done/` 은 **gitignore 됩니다.** 각자 자기 맥에만 쌓이는 개인 작업 기록입니다.

---

## 무엇을 기록하는가

**무엇을 바꿨는지는 기록하지 마십시오. `git log` 와 diff 가 이미 압니다.**

기록할 가치가 있는 것은 git 에 남지 않는 것들입니다:

| 담을 것 | 왜 |
|---|---|
| **결정과 근거** | 코드는 결과만 보여줍니다. 왜 그 선택이었는지는 사라집니다 |
| **시도했다 버린 것** | 다음 사람이 같은 길을 다시 걷지 않게 합니다. **가장 값진 항목** |
| **틀렸던 전제** | 문서나 계획이 사실과 달랐던 지점 |
| **남은 일 · 막힌 것** | 다음 세션의 출발점 |

담지 말 것: 파일별 변경 요약, 명령어 나열, 대화 재현.

## 1단계 — 저장 위치 확인

```bash
git rev-parse --show-toplevel        # 레포 루트
```

git 레포가 아니면 현재 디렉터리를 씁니다. `.done/` 이 없으면 만듭니다:

```bash
mkdir -p "<루트>/.done"
```

## 2단계 — gitignore 확인

**`.done/` 이 무시되지 않으면 개인 기록이 커밋에 딸려 들어갑니다.** 확인하고 없으면 추가합니다.

```bash
git check-ignore -q .done/ && echo "무시됨" || echo "추가 필요"
```

> ⚠️ **끝의 슬래시를 빼지 마십시오.** `.gitignore` 의 `.done/` 패턴은 **디렉터리에만** 매칭되는데,
> 폴더가 아직 없으면 git 이 디렉터리인지 알 수 없어 매칭에 실패합니다. 즉 `.done` 으로 물으면
> **이미 무시되고 있는데도 "추가 필요"** 가 나옵니다. 그대로 믿고 진행하면 `.gitignore` 에
> **중복 줄**을 넣게 됩니다. 슬래시를 붙이면 폴더 유무와 무관하게 바르게 판정합니다.

추가가 필요하다고 나왔더라도 **`.gitignore` 를 먼저 눈으로 확인하십시오.** 이미 있으면 아무것도
하지 마십시오.

```bash
grep -nE "^\.done/?$" .gitignore        # 이미 있으면 출력됨 = 추가하지 않는다
```

정말 없을 때만 레포 `.gitignore` 에 한 줄 넣고, **무엇을 왜 넣었는지 사용자에게 알립니다.**

```
# 세션 기록 — 개인 로컬 파일
.done/
```

## 3단계 — 파일 작성

파일명: `.done/<YYYY-MM-DD>-<HHMM>-<슬러그>.md`

슬러그는 세션의 주제를 짧은 한국어/영문으로 (`devkit-커맨드-추가`, `storage-버그-추적`).
하루에 여러 세션이 있어도 시각 때문에 겹치지 않습니다.

```markdown
# <세션 한 줄 제목>

> <YYYY-MM-DD HH:MM> · 브랜치 `<branch>` · 커밋 `<첫 sha>..<끝 sha>`

## 결정

- **<결정한 것>** — <왜 그렇게 했는지>

## 버린 시도

- **<시도한 것>** — <왜 버렸는지. 이게 이 기록의 핵심이다>

## 틀렸던 전제

- <문서나 계획이 사실과 달랐던 지점. 없으면 이 절을 지운다>

## 남은 일

- <다음 세션의 출발점. 막힌 것이 있으면 무엇에 막혔는지>

## 참고

- <관련 파일·PR·커밋·외부 문서 링크>
```

### 쓸 때

- **짧게.** 한 화면에 들어와야 다시 읽힙니다. 결정이 3개면 3줄입니다
- **"왜" 를 빠뜨리지 마십시오.** 근거 없는 결정 기록은 나중에 뒤집을 수도 지킬 수도 없습니다
- 세션에 기록할 결정이 없었다면 **그렇게 말하고 파일을 만들지 마십시오.** 빈 기록은 검색을 오염시킵니다

## 4단계 — 보고

저장 경로와 담은 항목 수를 알립니다. 파일 내용을 다시 늘어놓지 마십시오 — 방금 만든 것입니다.

---

## 나중에 조회하는 법

`.done/` 은 **세션 시작 때 통째로 읽는 곳이 아닙니다.** 컨텍스트만 낭비합니다.
"이거 왜 이렇게 됐지?" 류의 질문이 나올 때 검색합니다:

```bash
grep -rl "<키워드>" .done/ | sort -r        # 최근 것부터
ls -t .done/ | head -5                      # 최근 세션 5개
```

셸을 타지 않는 대안이 있습니다. **Glob 도구(`.done/*.md`)는 수정 시각 순으로 돌려주므로 그
자체로 최근 것부터입니다.** 파일명이 `YYYY-MM-DD-HHMM-` 으로 시작하니 결과만 봐도 언제
것인지 알 수 있습니다.

> ⚠️ **이름 오름차순은 오래된 것부터입니다.** `ls .done/` 이나 이름으로 정렬한 목록의 맨 위는
> **가장 오래된** 기록입니다. 최근 것을 원하면 위의 `ls -t` 나 `sort -r` 처럼 뒤집어야 합니다 —
> 여기서 헷갈리면 반대쪽을 읽고도 "최신" 이라고 보고하게 됩니다.

## 하지 말 것

- **`.done/` 을 커밋하지 마십시오.** 개인 기록입니다. 2단계에서 무시되는지 확인합니다
- **git 이 아는 것을 옮겨 적지 마십시오.** 파일 목록·변경 줄 수·커밋 메시지 나열은 중복입니다
- **성과를 부풀리지 마십시오.** 막힌 것은 막혔다고, 확인 못 한 것은 못 했다고 씁니다.
  이 기록의 독자는 미래의 자신이고, 낙관적인 기록은 그 사람을 속입니다
- 기존 파일을 덮어쓰지 마십시오. 세션마다 새 파일입니다
